# 算术运算

> [!目标]
> - 会用 `+ - * / %`，特别是**整数除法**和**取余**
> - 会用自增自减 `++ --` 和复合赋值 `+= -= *=`
> - 会做类型转换，会取整（`round`、`ceil`、`floor`）
> - 知道什么叫**溢出**，并能避开它

## 四则运算和取余

| 运算符 | 含义 | 例子（`a=7, b=2`） |
| :-: | :-- | :-: |
| `+` `-` `*` | 加、减、乘 | `a+b` 得 9，`a*b` 得 14 |
| `/` | 除 | `a/b` 得 **3** |
| `%` | 取余数（只能用于整数） | `a%b` 得 1 |

```cpp frag
int a=7,b=2;
cout<<a+b<<" "<<a-b<<" "<<a*b<<" "<<a/b<<" "<<a%b<<endl;
```

```output
9 5 14 3 1
```

注意最后两个：`7/2` 得到的是 **3**，不是 3.5。

## 整数除法：小数部分被直接丢掉

**两个整数相除，结果还是整数**，小数部分直接舍去（不是四舍五入）。想得到小数，至少让其中一个数是小数（`double`）：

```cpp frag
int a=7,b=2;
cout<<a/b<<endl;
cout<<7.0/2<<endl;
cout<<(double)a/b<<endl;
cout<<1.0*a/b<<endl;
```

```output
3
3.5
3.5
3.5
```

`(double)a` 的意思是“把 a 当成小数来用”，这叫**强制类型转换**。`1.0*a` 是另一个常用的小技巧：乘上一个小数，整个式子就变成小数运算了。

> [!注意] 把结果存进 `double`，不能挽救已经丢掉的小数
> 下面的 `7/2` 先按整数除法算出 3，**之后**才放进 `x`：
>
> ```cpp frag
> double x=7/2;
> cout<<x<<endl;
> ```
>
> ```output
> 3
> ```
>
> 要写成 `double x=7.0/2;` 才对。

## 取余 `%`：竞赛里最常用的运算之一

| 想做的事 | 写法（`n` 是整数） |
| :-- | :-- |
| 判断偶数 / 奇数 | `n%2==0` / `n%2==1` |
| 判断能否被 `k` 整除 | `n%k==0` |
| 取个位数字 | `n%10` |
| 去掉个位数字 | `n/10` |
| 让数字“绕圈”（比如 0~6 循环） | `i%7` |

拆出一个三位数的百位、十位、个位：

```cpp frag
int n=358;
cout<<n/100<<" "<<n/10%10<<" "<<n%10<<endl;
```

```output
3 5 8
```

> [!提示] 负数取余，结果的正负跟着左边走
> ```cpp frag
> cout<<-7%3<<" "<<7%-3<<endl;
> ```
>
> ```output
> -1 1
> ```
>
> 所以“判断奇数”最好写 `n%2!=0`，而不是 `n%2==1`（`-3%2` 是 -1）。

## 自增自减和复合赋值

`i++` 就是“`i` 加 1”，`i--` 是“减 1”。`a+=3` 是 `a=a+3` 的简写，其他运算也有同样的简写：`-=`、`*=`、`/=`、`%=`。

`++` 放在前面还是后面，在**单独成一句**时没有区别；当它参与别的运算时，区别就来了：

- **后置** `a++`：先用 `a` 现在的值，再加 1。
- **前置** `++a`：先加 1，再用新的值。

```trace
int a=5;                    //@s1
int b=a++;                  //@s2
int c=++a;                  //@s3
cout<<a<<" "<<b<<" "<<c;    //@s4
---
s1 | a=5 |  | a 是 5。
s2 | a=6; b=5 |  | 后置 a++：先把 a 当前的值 5 交给 b，然后 a 才加 1 变成 6。
s3 | a=7; b=5; c=7 |  | 前置 ++a：a 先加 1 变成 7，再把 7 交给 c。
s4 | a=7; b=5; c=7 | 7 5 7 | 输出三个变量现在的值。
```

> [!提示] 先别在一句话里混用
> 新手阶段，让 `++` 自己单独成一句最保险：`a++;`。

## 类型转换和取整

不同类型的数一起运算时，**小的会自动变大**：`int` 遇到 `double` 就变成 `double`。反过来，把小数赋给整数，**小数部分直接舍去**（不是四舍五入）：

```cpp frag
cout<<(int)3.9<<" "<<round(3.5)<<" "<<ceil(3.1)<<" "<<floor(3.9)<<endl;
```

```output
3 4 4 3
```

- `(int)3.9`：直接砍掉小数，得 3。
- `round(x)`：四舍五入。`ceil(x)`：向上取整。`floor(x)`：向下取整。

> [!竞赛] 整数的“向上取整”
> 要算“`a` 个东西，每组放 `b` 个，至少要几组”，就是向上取整。不用 `ceil`，用这个公式更稳：`(a+b-1)/b`。比如 `(7+2-1)/2` 等于 4。

## 溢出：数字太大，盒子装不下

`int` 最大约 21 亿。算出来的数超过它，就会“绕一圈”变成一个莫名其妙的值，而且**不会报错**。

```cpp frag
int a=100000,b=100000;
cout<<a*b<<endl;
cout<<(long long)a*b<<endl;
```

```output
1410065408
10000000000
```

第一行本该是 100 亿，却变成了 1410065408。第二行先把 `a` 转成 `long long` 再乘，就对了。

还有一个更隐蔽的坑：

```cpp frag
long long x=100000*100000;
long long y=100000LL*100000;
cout<<x<<" "<<y<<endl;
```

```output
1410065408 10000000000
```

等号右边的 `100000*100000` 是两个 `int` 相乘，**先溢出了**，之后再放进 `long long` 已经晚了。给其中一个数加上 `LL`（`100000LL`），或者提前转换类型，才能保住结果。

> [!竞赛] 看到“乘”和“累加”，先想会不会溢出
> 一旦担心 `int` 不够，就把相关的变量全部声明成 `long long`，输出也用 `%lld`。这是算法竞赛和洛谷里最容易“明明思路对了却只拿一半分”的原因。

## 数学函数

用到 `sqrt`、`pow` 这些函数，需要头文件 `<cmath>`，不过 `bits/stdc++.h` 已经全包含了。

```cpp frag
cout<<sqrt(16)<<" "<<pow(2,10)<<" "<<abs(-5)<<" "<<fabs(-2.5)<<" "<<max(3,8)<<" "<<min(3,8)<<endl;
```

```output
4 1024 5 2.5 8 3
```

> [!注意] `pow` 返回的是小数
> `pow` 算出来的是 `double`，有时会带一点点误差。要算整数的幂（比如 `2^10`），竞赛里常用循环乘，或者用位运算 `1<<10`，更稳。

## 练一练

> [!思考] 输入一个三位数，求它各位数字之和
> 比如 358，各位之和是 3+5+8=16。怎么用前面学的运算做到？

> [!答案] 参考写法
> 把百位、十位、个位分别取出来再相加：
>
> ```cpp frag
> int n=358;
> cout<<n/100+n/10%10+n%10<<endl;
> ```
>
> ```output
> 16
> ```

> [!小结]
> - 整数 `/` 整数，结果仍是整数（直接舍去小数）；要小数，让其中一个变成 `double`。
> - `%` 取余：判断奇偶、整除、取个位，用得非常多。
> - `a++` 先用后加，`++a` 先加后用；`+=` 这类是简写。
> - `int` 装不下就换 `long long`，乘法之前就要转换，别等溢出之后再补救。
