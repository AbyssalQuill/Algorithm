# 用类封装数据结构

> [!目标]
> - 理解在算法竞赛里把数据结构写成类的好处：可以创建多个、方便复用、接口清晰
> - 能写出并查集的类，知道它的两个关键优化
> - 能用重载 `*` 的矩阵类配合快速幂，求出很大的斐波那契数

## 为什么比赛里也要用类

多数竞赛题目的代码是“全局数组加几个函数”，写起来最快。可是一旦出现下面这些情形，这种写法就开始吃力：一道题里需要两套同样的数据结构，全局数组得复制一份并改名；想把写好的数据结构留作模板，在别的题里复用，就得把它散落的数组、函数一起摘出来；函数之间靠全局变量沟通，漏掉一次初始化，错误很难查。

把数据结构写成类，这些问题就都消失了：数据和操作被绑在一起，需要几个就创建几个对象，用的时候只关心它提供哪些成员函数，不必在意内部怎么存放。这正是前面几课学过的构造函数、封装和运算符重载在竞赛里最实用的地方。

## 例一：并查集

并查集要解决的问题是：有若干个元素，开始时每个元素自成一组。需要支持两种操作：把两个元素所在的组合并成一组，以及询问两个元素是否在同一组。

实现的办法是用 `fa[x]` 记录元素 `x` 的“上一级”，每一组对应一棵树，树根是这一组的代表。`find(x)` 顺着 `fa` 一路向上找到树根，两个元素的树根相同，就说明在同一组；合并则是让一个树根挂到另一个树根下面。

```cpp title="dsu.cpp"
#include <bits/stdc++.h>
using namespace std;
class DSU{
    vector<int> fa,sz;
public:
    DSU(int n): fa(n+1), sz(n+1,1){
        iota(fa.begin(),fa.end(),0);
    }
    int find(int x){
        return fa[x]==x?x:fa[x]=find(fa[x]);
    }
    bool merge(int a,int b){
        a=find(a);
        b=find(b);
        if (a==b) return false;
        if (sz[a]<sz[b]) swap(a,b);
        fa[b]=a;
        sz[a]+=sz[b];
        return true;
    }
    bool same(int a,int b){
        return find(a)==find(b);
    }
    int size(int x){
        return sz[find(x)];
    }
};
int main(){
    int n,m;
    cin>>n>>m;
    DSU d(n);
    while (m--){
        int op,x,y;
        cin>>op>>x>>y;
        if (op==1){
            d.merge(x,y);
        }else{
            cout<<(d.same(x,y)?"Y":"N")<<endl;
        }
    }
    return 0;
}
```

```input
5 6
1 1 2
1 3 4
2 1 3
1 2 3
2 1 4
2 1 5
```

```output
N
Y
N
```

输入里 `1 x y` 表示合并，`2 x y` 表示询问。前两次合并得到 `{1,2}` 和 `{3,4}` 两组，所以 1 和 3 不在一起，回答 `N`；随后合并了 2 和 3，两组并成 `{1,2,3,4}`，1 和 4 就在一起了，回答 `Y`；5 始终是单独的一组，回答 `N`。

这个类里藏着两处重要的优化。`find` 里的 `fa[x]=find(fa[x])` 叫**路径压缩**：找到树根后，把沿途所有的结点都直接挂到树根下面，下一次再找就几乎一步到位。`merge` 里比较 `sz` 的做法叫**按大小合并**：总是把小的树挂到大的树下面，避免树越长越高。两者配合，每次操作的平均时间几乎是常数。

`fa` 和 `sz` 是私有的，类的使用者没有办法绕过 `merge` 直接去改树的结构，所以不会因为误操作破坏它的内部状态。如果需要同时维护两种不同的分组关系，只要再创建一个 `DSU` 对象即可。

## 例二：矩阵与快速幂

斐波那契数列 `F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2)`。当 `n` 大到 10 的十八次方时，一项项地递推显然来不及。观察下面的等式：

```text
| F(n+1) F(n)   |   | 1 1 | ^ n
| F(n)   F(n-1) | = | 1 0 |
```

也就是说，只要把矩阵 `[[1,1],[1,0]]` 自乘 `n` 次，结果右上角的元素就是 `F(n)`。矩阵自乘可以像整数的快速幂一样，每次把指数折半，只需要大约 `log n` 次矩阵乘法。

把矩阵写成一个类，并重载 `*`，主体代码就能写得和数学公式几乎一模一样。

```cpp title="matrix.cpp"
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const ll MOD=1000000007;
struct Matrix{
    ll a[2][2];
    Matrix(){
        memset(a,0,sizeof a);
    }
    static Matrix identity(){
        Matrix m;
        m.a[0][0]=m.a[1][1]=1;
        return m;
    }
    Matrix operator*(const Matrix &o) const{
        Matrix r;
        for (int i=0;i<2;i++){
            for (int j=0;j<2;j++){
                for (int k=0;k<2;k++){
                    r.a[i][j]=(r.a[i][j]+a[i][k]*o.a[k][j])%MOD;
                }
            }
        }
        return r;
    }
};
Matrix power(Matrix b,ll e){
    Matrix r=Matrix::identity();
    while (e>0){
        if (e&1) r=r*b;
        b=b*b;
        e>>=1;
    }
    return r;
}
int main(){
    ll n;
    cin>>n;
    Matrix m;
    m.a[0][0]=m.a[0][1]=m.a[1][0]=1;
    cout<<power(m,n).a[0][1]<<endl;
    return 0;
}
```

```input
50
```

```output
586268941
```

`F(50)` 的准确值是 12586269025，对 1000000007 取余后是 586268941。`power` 里的 `r=r*b` 和 `b=b*b` 读起来就是快速幂的标准写法，完全看不到矩阵元素的下标运算，这些细节都被封装进了 `operator*`。`identity` 是单位矩阵，作用相当于整数乘法里的 1，用来作为累乘的起点。

`identity` 前面的 `static` 表示它属于类而不属于某个具体的矩阵，不需要先有一个对象才能调用，所以写成 `Matrix::identity()`。

> [!注意] 两个取模后的数相乘，最大接近 10 的十八次方，仍然小于 `long long` 的上限，所以乘法的每一步之后立刻取余是安全的。如果模数更大，乘积就可能溢出，需要换成 `__int128` 或者更特别的乘法。

## 什么时候选择写成类

小题目、只用一次的结构，仍然是全局数组加函数最快，没有必要为了形式去套一层类。下面几种情形，写成类会更合算：

| 情形 | 为什么适合写成类 |
| --- | --- |
| 同一种结构需要多个实例 | 每个对象有自己的数据，不会互相干扰 |
| 准备放进自己的代码模板库 | 对外只暴露少数几个成员函数，使用时不必重新理解内部细节 |
| 结构有需要保持的约定 | 把数据设为私有，约定只在成员函数里维护一次 |
| 需要用运算符表达计算 | 矩阵、分数、大整数用 `*`、`+` 写出来更接近原来的数学表达 |

> [!竞赛] 并查集、线段树、树状数组、矩阵、分数、大整数，都是很适合写成类的内容。平时把它们写成能直接复制使用的类，整理进模板库，比赛时就能不假思索地调用。

> [!思考] 如果把并查集里的路径压缩去掉，只保留按大小合并，`find` 的复杂度大约是多少？

> [!答案] 参考思路
> 按大小合并保证每次让小树挂到大树下，一个结点每次因为合并而更深一层，所在树的大小至少翻倍，所以树的高度不超过 `log n`，`find` 的复杂度是 `O(log n)`。路径压缩则能让它进一步降到几乎常数。

> [!小结]
> 把数据结构写成类，可以让数据和操作绑在一起，创建多个互不干扰的对象，也方便整理成模板反复使用。并查集的类用路径压缩和按大小合并，让每次操作的平均代价几乎是常数；矩阵类重载 `*`，配合快速幂就能在对数时间内求出巨大的斐波那契数。
