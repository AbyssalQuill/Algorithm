# 递归入门

> [!目标]
> 读完这一课，你应该理解递归就是函数调用它自己，掌握递归的三个要素，会写阶乘、求和、斐波那契这几个经典例子，并且知道递归的调用栈以及它有深度限制。

## 函数调用它自己

函数里面可以调用别的函数，也可以调用它自己，这种做法叫作**递归**。先看一个最简单的例子：从给定的数开始倒数到 1。

```cpp title="down.cpp"
#include <bits/stdc++.h>
using namespace std;
void down(int n){
    if (n==0){
        return;
    }
    cout<<n<<" ";
    down(n-1);
}
int main(){
    down(3);
    cout<<endl;
    return 0;
}
```

```output
3 2 1
```

`down(3)` 先输出 3，然后把剩下的工作交给 `down(2)`；`down(2)` 输出 2，再交给 `down(1)`；直到 `n` 变成 0，函数什么也不做就返回，之前被层层“搁置”的调用才依次结束。

## 递归的三个要素

要写出正确的递归，需要想清楚三件事。第一是**终止条件**，也就是什么情况下不再继续调用自己，上面的例子里是 `n==0`；没有它，函数会一直调用下去，直到程序崩溃。第二是**缩小规模**，每次调用时，问题必须比上一层更小（例子里 `n` 减了 1），这样才会一步步靠近终止条件。第三是**调用自己**：把规模更小的同类问题交给自己去解决，并且相信它给出的结果是对的，再用这个结果推出当前问题的答案。

## 经典例子：阶乘

n 的阶乘是 1 到 n 所有整数的乘积，可以写成 `n! = n × (n-1)!`，并且 `1! = 1`。这恰好是“大问题依赖同类小问题”的结构：

```cpp title="fact.cpp"
#include <bits/stdc++.h>
using namespace std;
int fact(int n){
    if (n<=1){
        return 1;
    }
    return n*fact(n-1);
}
int main(){
    cout<<fact(5)<<endl;
    return 0;
}
```

```output
120
```

下面用 `fact(3)` 来看看内部发生了什么。右边显示的“栈”，是当前还没有执行完、正在等待结果的函数，最新的一层排在最右边：

```trace
#include <bits/stdc++.h>
using namespace std;
int fact(int n){
    if (n==1) return 1;           //@s3
    return n*fact(n-1);           //@s4
}
int main(){
    cout<<fact(3);                //@s1
    return 0;
}
---
s1 | 栈=fact(3) |  | main 调用 fact(3)，进入第一层。
s3 | 栈=fact(3); n=3 |  | 第一层中 n 是 3，不等于 1，还不能直接给出答案。
s4 | 栈=fact(3); n=3 |  | 需要计算 3*fact(2)。第一层先等着，转去调用 fact(2)。
s3 | 栈=fact(3) ▸ fact(2); n=2 |  | 进入第二层，n 是 2，同样不等于 1。
s4 | 栈=fact(3) ▸ fact(2); n=2 |  | 需要 2*fact(1)，第二层也暂时等待，再去调用 fact(1)。
s3 | 栈=fact(3) ▸ fact(2) ▸ fact(1); n=1 |  | 进入第三层，n 是 1，满足终止条件，直接返回 1，不再往下调用。
s4 | 栈=fact(3) ▸ fact(2); n=2; 得到=2 |  | 回到第二层，计算 2*1=2，把 2 返回，第三层随之结束。
s4 | 栈=fact(3); n=3; 得到=6 |  | 回到第一层，计算 3*2=6，把 6 返回，第二层随之结束。
s1 | 栈=空; 得到=6 | 6 | 回到 main，拿到结果 6 并输出。
```

整个过程可以概括为：一层层向里调用，直到遇到终止条件，然后带着结果一层层往外返回。这些叠在一起、等待结果的函数叫作**调用栈**，之后学习“栈”这种数据结构时，还会再次遇到它。

## 更多的例子

求 `1+2+…+n` 可以写成 `sum(n) = n + sum(n-1)`，终止条件是 `sum(0)=0`。求最大公约数的辗转相除法本身就是递归的：`gcd(a,b)` 等于 `gcd(b, a%b)`，当 `b` 为 0 时，答案就是 `a`。

```cpp title="gcd.cpp"
#include <bits/stdc++.h>
using namespace std;
int gcd(int a,int b){
    return b==0?a:gcd(b,a%b);
}
int main(){
    cout<<gcd(12,18)<<endl;
    return 0;
}
```

```output
6
```

再看汉诺塔：把 `n` 个盘子从一根柱子搬到另一根，需要先把上面的 `n-1` 个搬开，再搬最大的那一个（1 步），最后把 `n-1` 个搬回来。设搬 `n` 个盘子需要 `h(n)` 步，则 `h(n)=2*h(n-1)+1`。

```cpp title="hanoi.cpp"
#include <bits/stdc++.h>
using namespace std;
int hanoi(int n){
    if (n==0){
        return 0;
    }
    return 2*hanoi(n-1)+1;
}
int main(){
    cout<<hanoi(3)<<endl;
    return 0;
}
```

```output
7
```

## 斐波那契数列与递归的陷阱

斐波那契数列的前几项是 1, 1, 2, 3, 5, 8……从第三项起，每一项都是前两项之和。把它写成递归，几乎就是照着定义抄一遍：

```cpp title="fib.cpp"
#include <bits/stdc++.h>
using namespace std;
int fib(int n){
    if (n<=2){
        return 1;
    }
    return fib(n-1)+fib(n-2);
}
int main(){
    cout<<fib(10)<<endl;
    return 0;
}
```

```output
55
```

写法虽然简洁，却有一个严重的问题。计算 `fib(5)` 要调用 `fib(4)` 和 `fib(3)`，而 `fib(4)` 又会再次调用 `fib(3)`，同一个值被反复计算了很多遍。随着 `n` 增大，重复的次数呈指数级增长，`fib(40)` 要调用大约 3 亿次，程序会慢到超时。

> [!竞赛] 对策是把算过的结果记下来
> 把算过的 `fib(k)` 存进数组，下次需要时直接取用，就能把指数级的时间降到线性。这种做法称为记忆化，它也是后面要学的动态规划的雏形。写递归时，要留意会不会出现大量的重复计算。

## 递归的深度是有限的

每一层递归都要占用一小块内存。如果层数太多，比如递归了十几万层，就会发生**栈溢出**，程序直接崩溃（常见的表现是“运行错误”）。所以递归层数大约只能到几万层，而不是无穷无尽的。

因此，能用循环轻松解决的问题（比如求 1 加到 n），优先用循环；而递归更适合那些“天然就是大问题套小问题”的场合，比如以后要学的搜索、分治和树。

> [!思考] 用递归求 1+2+…+n，并算出 `sum(10)`

> [!答案] 参考写法
> `sum(n)=n+sum(n-1)`，终止条件是 `n==0`：
>
> ```cpp title="sum.cpp"
> #include <bits/stdc++.h>
> using namespace std;
> int sum(int n){
>     if (n==0){
>         return 0;
>     }
>     return n+sum(n-1);
> }
> int main(){
>     cout<<sum(10)<<endl;
>     return 0;
> }
> ```
>
> ```output
> 55
>```

> [!小结]
> 递归就是函数调用自己，写之前先想清楚终止条件、怎样缩小规模以及如何利用子问题的结果。执行时先一层层向里调用，到达终止条件后再一层层带着结果返回，等待中的函数构成调用栈。层数过深会栈溢出，重复计算过多会超时，需要时用记忆化或改写成循环。
