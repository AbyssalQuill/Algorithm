# 课文写作规范

这份规范约定了教程里的文字应该怎么写。目的只有一个：让读的人觉得是一位认真负责的老师在当面讲，而不是一份拼出来的模板。

## 说话的方式

1. **先讲为什么，再讲怎么做。** 每引入一个概念，先说它是为了解决什么麻烦，再给出做法。读者知道了动机，就不容易死记硬背。
2. **用完整的句子，用关联词把它们连起来。** “因为……所以……”“如果……就……”“换句话说……”这些词承担了讲道理的工作。连续出现三句以上的短句并列，读起来像清单，要么合并，要么补上它们之间的关系。
3. **句子长短交替。** 一段话里既要有能把事情讲完整的长句，也要有用来收束的短句，但不要让所有句子都一个长度、一个结构。
4. **语气平实克制。** 不卖萌，不喊口号，不使用感叹号，不用“别慌”“小提示”“啦”这类口语装饰。对读者偶尔用“你”，不必每句都用。
5. **术语第一次出现时用一句朴素的话解释。** 之后统一叫法，不要同一个东西一会儿叫“盒子”一会儿叫“容器”。

## 标题

- 用名词短语或者直接的问题，说明这一节讲什么：“为什么需要循环”“if 语句的执行顺序”“常见的编译错误”。
- 不用口号式、比喻式、带语气的标题，例如“让它一步步跑给你看”“写给人看的话”“别慌”。
- 同一课里的标题长度和结构尽量不同，避免一排“X：Y”。

## 结构

- 列表只在内容本来就是并列项时使用（步骤、对照、清单）。一段道理不要硬拆成三个等长的要点。
- 提示框要克制。**注意**只放会让程序出错的事；**竞赛**只放与比赛直接相关的做法；**目标**用一两句话说明读完能做什么；**小结**用一小段话回顾这一课的核心关系，不要把前文的标题再列一遍。
- 示例先给完整、能运行的程序，再拆开讲。数字具体，输出写全。

## 用词

- 不出现具体赛事名，统一说“算法竞赛”。
- “蓝桥杯”“洛谷”等只在确有必要引用题目来源时出现（洛谷题目除外）。
- 代码里的名字、注释和课文里的说法保持一致。
